# Co-Breathing v4.0 实施计划

## Phase 0：仓库与无硬件骨架（当前）

- 建立 v3.3 `main` 基线，隔离 `maps_network/` 和大型历史资产。
- 在 `codex/v4-architecture` 工作，归档 v3.3 文档并升级 v4.0。
- 新建 `shared`、`china`、`austria` 和 `tools` 边界。
- 完成消息校验、人物容量选择、鱼群聚合、两方向映射和程序退流。
- 配置全部使用 `noop`，以单条命令运行双站 dry-run。
- 保持旧 Python 71 项和 TypeScript 17 项测试通过并增加 v4 测试。

完成标准：无硬件环境中 dry-run 验证正常、2 秒退流、10 秒稳定恢复、5 秒渐变与 `SAFE_OFF`，退出码 0。

## Phase 1：感知后端

- 奥地利 Hailo-8 YOLOv8s + ByteTrack 正式后端和 YOLOv8n NCNN 416/320 CPU 退格已接入同一运行入口。
- 在实际 Pi 用固定视频集运行 30 分钟基准；最低状态 5 Hz，目标 10 Hz。
- 已完成 20 秒实时流 Hailo 短测；尚需固定视频集、30 分钟持续测试和 Hailo PCIe 驱动告警解决后才能完成验收。
- 中国固定机位先接背景差分/轮廓与短时轨迹；证据表明不合格时才接轻量 YOLO。

## Phase 2：本地通信与执行器

- 中国实现 Mac → USB Serial → ESP32-S3 协议和 16 路震动 no-load 测试。
- 奥地利完成 PCA9685/MOSFET 单泵台架、雾化定时开关和通道映射。
- 锁定电源、PWM、斜坡、最大占空比、最大同时泵数和雾化周期。
- 完成实体急停、看门狗、`OE` 上拉、进程冻结和掉电测试后，才允许真实驱动配置。

## Phase 3：跨国网络

- 比较候选 MQTT broker 区域的双端 RTT、抖动、丢包和恢复时间。
- 配置 TLS/WSS 443、证书、ACL、主题和流量限制。
- 验证乱序、重复、未来时间、TTL、断线、重连和 retained 旧值不会驱动负载。

## Phase 4：双站联调与展陈

- 中国 3–5 只真实鱼与奥地利观众同时闭环。
- 校准坐标、活动量、震动场、泵场和薄膜响应。
- 进行 8 小时运行、断网、过温、进程崩溃、急停和恢复演练。
- 冻结版本、离线安装包、备件、接线图、操作手册和回退流程。

## 仍待实测

broker 区域、动物福利阈值、泵 PWM、看门狗型号、雾化参数、Mac mini 型号、摄像头和 AI HAT 机械堆叠；这些不阻塞 Phase 0。
